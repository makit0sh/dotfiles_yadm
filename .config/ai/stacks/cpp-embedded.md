# C++ / 組み込み(仕事)

`AGENTS.md` の上に載る分。**ここに書いてよいのは、どこの職場でも通じる一般論だけ。**
雇用主固有のコーディング規約・社内ツール・製品名・コード片は、この個人 dotfiles
リポジトリに置かない(職場のリポジトリか、追跡外のファイルへ)。

## ビルドと再現性

- ビルドの再現性を最優先に扱う。**手元で通ったことは、他所で通る根拠にならない**
  (ツールチェーンの版・libc・カーネルヘッダ)
- コンパイラとツールチェーンの版を宣言で持つ。`CMakeLists.txt` に暗黙の
  ホスト依存を残さない
- クロスコンパイルとネイティブビルドのどちらで検証したかを、必ず報告に書く

## C++ の書き方

- 所有権を型で表す(生ポインタを所有に使わない)。ライフタイムが自明でない
  ものは、なぜ安全かをコメントに書く
- **未定義動作を「動いているから良い」で通さない。** サニタイザ(ASan/UBSan)を
  通せるものは通す
- 例外を使うか使わないかはプロジェクトの決定。**混在させない**
- ヘッダの include はコストなので、前方宣言で済むものは前方宣言

## 組み込み固有

- 割り込みコンテキストで何をしてよいかを常に意識する(確保・ブロック・ログ)
- タイミング依存の不具合は、**再現手順が書けるまで直したと言わない**
- リソース(スタック・ヒープ・フラッシュ)の見積もりを、変更のたびに更新する
- ログを増やすと挙動が変わりうる。計測手段が対象を変えていないか疑う

## 検査

- 静的解析(clang-tidy)とフォーマット(clang-format)は CI と同じ設定で手元でも回す
- 実機でしか出ないものがある。**実機で見ていないなら「未確認」と書く**
