# Linux カーネル / ドライバ(仕事)

`core.md` と `cpp-embedded.md` の上に載る分。一般論のみ。

## 前提

- **カーネル空間には C++ の常識を持ち込まない。** 例外なし、浮動小数点なし、
  スタックは小さい(数 KB)。大きなローカル変数を置かない
- コーディングスタイルは `Documentation/process/coding-style.rst` が正。
  `scripts/checkpatch.pl` を通す
- ライセンスの含意を意識する。**GPL のシンボルに依存するかどうかは設計判断**

## コンテキスト

- **今どのコンテキストにいるかを常に言えること**(プロセス / ソフト IRQ /
  ハード IRQ / atomic)。ここを取り違えたスリープが最も多い事故
- ロックは種類と順序を決めて文書化する。`lockdep` を有効にして走らせる
- ユーザ空間からのポインタは必ず `copy_from_user` 系を通す。**境界の検査を
  省いてよい理由は無い**

## デバッグ

- `printk` は挙動を変えうる(タイミング)。ftrace / trace_printk を優先する
- oops/panic は**スタックトレースを丸ごと**残す。要約すると原因が消える
- KASAN / KMEMLEAK を通せる構成なら通す

## 検査

- ビルドが通ることと、ロードして動くことと、外して安全に戻ることは別の3つ。
  **rmmod まで確認していないなら「未確認」と書く**
- カーネル版を跨ぐ API 変更は静かに壊れる。対象版を明示する
