# ROS 2(仕事)

`core.md` と `cpp-embedded.md` の上に載る分。一般論のみ(`cpp-embedded.md` の
冒頭の但し書きが同じように効く)。

## 構造

- ノードの責務を1つに保つ。**「ついでにここでも publish する」を足さない** —
  トピックの流れが読めなくなると、後から誰も因果を追えない
- パラメータはコードに埋めず宣言する(`declare_parameter`)。既定値と単位を
  必ず書く。**単位はコメントではなく名前に入れる**(`timeout_ms`)
- QoS はデフォルト任せにしない。**publisher と subscriber の QoS 不一致は
  「繋がらない」ではなく「静かに何も来ない」**という形で出る

## ライフサイクルと時間

- `rclcpp::Time` と `std::chrono` を混ぜない。シミュレーション時間
  (`use_sim_time`)で挙動が変わる箇所を意識する
- スピナーとコールバックグループの選択(単一/再入可能)を、なぜそれかを
  書いた上で決める。デッドロックはここから来る

## デバッグ

- `ros2 topic hz` / `ros2 topic echo` で**実際に流れていること**を見てから
  ロジックを疑う。繋がっていない状態は、壊れている状態と見分けが付きにくい
- rosbag で再現できないタイミング不具合は、再現条件を先に書く

## 検査

- launch ファイルまで含めて起動確認する。**ノード単体のテストが通ることと、
  システムが立ち上がることは別**
- 実機とシミュレータのどちらで確認したかを報告に必ず書く
