# 作業の進め方(エージェント非依存・スタック非依存)

このファイルは **Claude Code / GitHub Copilot など、どのエージェントからも読まれる
共通の指示**。エージェント固有の設定(モデル・権限・アカウント)はここに書かない。

置き場所が `~/.claude/` ではなく `~/.config/ai/` なのは、**同じ内容を複数の
エージェントから参照したい**から。VSCode の Settings Sync は VSCode の中しか
運べず、Claude Code は VSCode の外にいるので、どちらかに閉じ込めると片方に届かない。

- 読み込み経路: `~/.claude/CLAUDE.md` が `@` import する(class ごとに読む
  スタックが違う。`~/.config/yadm/README` 相当は dotfiles の README を参照)
- **会社固有の規約・社内ツール・コード片をここに書かないこと。** この dotfiles は
  個人の GitHub リポジトリにある。ここに置いてよいのは「どこの職場でも通じる一般論」
  だけで、雇用主固有のものは職場のリポジトリか、追跡外のファイルに置く

---

## 言語

- 応答は日本語。**コード・コメント・コミットメッセージは英語**
- ドキュメントは読み手で決める。個人プロジェクトの `doc/` は日本語で構わない

## 事実の扱い

- **実測していないことを実測したように書かない。** 確認できなかったものは
  「未確認」と明記する。曖昧に流すより、確認できていないと言うほうが役に立つ
- 数字を引用するときは出典と取得日を添える。古くなる数字は、古くなったと
  気づける形で書く(自動更新すると、数字だけ新しくて周りの主張が嘘になる)
- 他のエージェントやツールの出力を額面通り受け取らない。**おかしければ確かめる**

## 検証

- **exit code をパイプで潰さない。** `cmd | tail` は `cmd` の失敗を隠す
- テストを「代用」しない。`pnpm test` の代わりに一部だけ走らせて green と
  報告しない
- 変更したら、その変更が壊しうるものを実際に動かす。**型検査とユニットテストが
  構造的に見られない層がある**(ブラウザ、ネットワーク、DB、権限)ことを前提に置く

## 変更の出し方

- **頼まれた範囲を勝手に狭めない・広げない。** 途中で問題を見つけたら、
  ひとこと述べてから、頼まれたことは最後までやる
- 手を止めて聞くのは、**どちらに解釈しても手戻りが大きい**ときだけ。
  それ以外は判断して進め、判断したことを報告に書く
- 破壊的・外向きの操作(push、外部への送信、削除、上書き)は事前に確認する

## コメントとドキュメント

- **「何をしているか」ではなく「なぜそうなっているか」を書く。** とくに
  「なぜ素直な方法ではないのか」は、書かないと次に必ず素直な方法に戻される
- 実際に踏んだ失敗は、日付と症状ごと残す。抽象化すると再発防止にならない
- 回避策を複数の場所に写経しはじめたら、直すべきは手順書ではなく原因

## 私について

- 個人開発(macOS / Windows WSL2)と、仕事(Ubuntu・組み込み)で環境が違う。
  **片方でしか動かない手順を既定にしない**
- 一人でメンテナンスしている。**守れない約束を仕組みに書かない**ほうが良い
